# 本地网站启动、登录与测试指导

适用：当前电脑 `D:\CodeX\kxkms` 工作区、DSSAST CMS 0.3.0。本文根据实际启动脚本和账号准备脚本编写，不包含密码。

## 1. 本地环境在哪里

当前工作区已准备 PHP、WordPress 和 SQLite 数据库，不需要另外启动 MySQL、Apache 或安装 PHP。

| 位置（相对于工作区） | 用途 |
| --- | --- |
| `.local-test/php/php.exe` | PHP 运行程序 |
| `.local-test/wordpress/` | 本地网站文件 |
| `.local-test/wordpress/wp-content/plugins/dssast-cms/` | 网站实际加载的插件副本 |
| `dssast-cms/` | 开发源代码；修改后需要复制到上面的插件目录 |
| `.local-test/LOCAL-LOGIN.txt` | 管理员、学生账号密码，以及已有测试页面地址 |
| `.local-test/start-local.ps1` | 启动网站 |
| `.local-test/stop-local.ps1` | 停止网站，保留数据库 |
| `.local-test/server-error.log` | 服务器错误日志 |

`.local-test/` 已被 Git 忽略。只从 GitHub 克隆仓库的新电脑不会自带这些文件，本文启动命令适用于当前已准备好的电脑。换电脑需要先另行安装 WordPress/PHP/数据库，或迁移完整本地环境，不能仅凭插件目录启动网站。

## 2. 启动网站

打开 Windows PowerShell，执行：

```powershell
Set-Location 'D:\CodeX\kxkms'
powershell -NoProfile -ExecutionPolicy Bypass -File .\.local-test\start-local.ps1
```

此命令只对本次脚本进程使用 ExecutionPolicy Bypass，不修改系统全局策略。网站在后台运行，不会弹出额外服务器窗口。

浏览器打开：

- 网站首页：<http://127.0.0.1:8097/>
- 管理后台：<http://127.0.0.1:8097/wp-admin/>
- 登录页面：<http://127.0.0.1:8097/wp-login.php>

请统一使用 `127.0.0.1:8097`，不要改成 localhost 或别的端口。这个地址仅供当前电脑访问，不是已部署的公网网站。首页没有展示模块入口时，按下文使用测试页面地址。

如果提示端口 8097 已被占用，先访问上述地址；可能网站已经启动。若打开的是其他程序，先确认端口使用者，不要直接结束不明进程。

## 3. 在哪里找用户名和密码

用记事本打开本地凭据文件：

```powershell
notepad 'D:\CodeX\kxkms\.local-test\LOCAL-LOGIN.txt'
```

文件按角色列出 `Username` 和 `Password`：

| 角色 | 用户名 | 用途 |
| --- | --- | --- |
| administrator | `dssast_local_admin` | 登录后台，管理赛事、审核笔记、管理新闻公告 |
| subscriber | `dssast_local_student` | 在前台测试笔记投稿 |

密码以文件中最新的 `Password` 为准，本文不复制密码。文件末尾还有“赛事一览”和“笔记投稿”的实际页面地址，请直接复制使用，不要猜测 page_id。

在登录页输入管理员账号及对应密码，登录后进入后台。学生测试建议使用浏览器无痕窗口，输入学生账号，然后打开文件中的“笔记投稿”页面。学生看不到管理员菜单属于正常权限限制。

### 密码失效或账号文件丢失

仅在需要重置本地测试账号时执行：

```powershell
Set-Location 'D:\CodeX\kxkms'
& .\.local-test\php\php.exe .\.local-test\prepare-manual.php
notepad .\.local-test\LOCAL-LOGIN.txt
```

这个脚本会重新生成两个账号的密码、设置管理员/订阅者角色、启用插件、补建赛事一览和笔记投稿页面，并设置测试站点名称、上海时区及可用的测试主题。旧密码随之失效，已有登录可能需要重新登录。它不是每次启动都要执行的步骤；只用于本地测试站。

## 4. 确保测试的是最新插件

开发目录和网站插件目录是两份文件。修改代码后，在工作区执行：

```powershell
Set-Location 'D:\CodeX\kxkms'
Copy-Item .\dssast-cms\* .\.local-test\wordpress\wp-content\plugins\dssast-cms -Recurse -Force
```

这会覆盖本地网站的插件文件，不会覆盖数据库。登录“插件 → 已安装插件”，确认 DSSAST CMS 已启用且版本为 0.3.0，再刷新编辑页面。若在网站插件副本中手工修改过代码，应先保存这些修改。

## 5. 推荐测试顺序

以下是待执行的手工测试，不代表已经全部通过。

### 赛事管理与添加页面

1. 管理员进入“内容管理 → 添加赛事”，或左侧“赛事 → 添加赛事”。
2. 确认页面出现标题、经典正文编辑器、发布面板和“赛事信息”，不再空白。
3. 输入测试标题、介绍，填写状态、赛事日期、报名起止时间与 `https://example.com/` 测试链接。
4. 保存草稿并重新打开，确认字段仍在；随后发布。
5. 打开凭据文件中的“赛事一览”，确认赛事出现；点击标题检查详情页的状态、时间和报名链接。
6. 将状态改成“已结束”并更新，检查前台变化。再测试报名截止早于开始的情况，应提示业务字段未保存并保留原值。

赛事状态是手动维护的业务进度，不会随时间自动变化。草稿不会出现在公开列表。

### 笔记投稿与审核

1. 无痕窗口以学生账号登录，打开“笔记投稿”页面。
2. 提交一篇笔记，确认显示“待审核”。新投稿每分钟最多一篇。
3. 管理员进入“内容管理 → 待审核笔记”，打开投稿，填写审核意见并勾选“退回作者修改”，保存。
4. 学生刷新投稿页，点击“修改再提交”，检查审核意见，修改后提交。
5. 管理员取消退回勾选并发布，确认状态为已发布。

### 新闻、公告和公开列表

1. 管理员在“内容管理”分别点击“添加新闻”“添加公告”。
2. 填写标题正文，检查分类对应“新闻”或“公告”后发布。
3. 进入“页面 → 新建页面”，插入“短代码”区块，按需创建以下列表页面并发布：

| 页面 | 短代码 |
| --- | --- |
| 公开笔记 | `[dssast_notes]` |
| 新闻列表 | `[dssast_news]` |
| 公告列表 | `[dssast_news category="dssast-announcement"]` |

通过“查看页面”访问实际地址，确认公开内容出现，草稿不出现。这三个页面不由账号准备脚本自动创建，也不保证自动加入首页导航。

### 秀米同步

在“内容管理 → 秀米同步设置”或“工具 → 秀米同步”检查配置说明及接口地址。未配置应用密钥时，同步接口关闭是正常行为。

真实秀米服务器不能回调本机的 `127.0.0.1`。真实同步需要秀米应用、绑定账号以及可从公网访问的 HTTPS 测试站点，配置步骤见 [XIUMI.md](XIUMI.md)。本机可测试后台和模拟接口，但不能据此认定真实同步成功；未准备联调环境时将此项记录为“阻塞”。同步稿应进入新闻分类的草稿，审核后手动发布。

## 6. 停止网站与下次继续

```powershell
Set-Location 'D:\CodeX\kxkms'
powershell -NoProfile -ExecutionPolicy Bypass -File .\.local-test\stop-local.ps1
```

停止后数据库与文章保留。下次执行启动命令即可，不需要重置账号或重新安装插件。电脑重启后也需重新启动网站。

## 7. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 浏览器提示无法连接 | 确认已执行启动脚本、端口是 8097，查看错误日志 |
| 找不到启动脚本或 PHP | 确认进入当前工作区；新克隆仓库不包含被忽略的本地环境 |
| 登录失败 | 从 LOCAL-LOGIN.txt 复制最新密码，注意区分管理员和学生；必要时使用重置步骤 |
| 看不到内容管理或赛事菜单 | 使用管理员登录，确认插件启用，复制最新插件后刷新 |
| 添加赛事仍空白 | 记录地址、浏览器控制台错误和服务器日志；不能仅凭语法测试通过认定页面正常 |
| 赛事/笔记详情链接 404 | 在“设置 → 固定链接”选择“朴素”并保存，再从列表重新点击链接；当前 PHP 内置服务器没有配置生产环境的伪静态规则 |
| 首页找不到赛事或投稿入口 | 打开 LOCAL-LOGIN.txt 末尾的测试页面地址，页面不会自动加入首页导航 |
| 修改源码后没有变化 | 重新复制到网站实际插件目录，再刷新浏览器 |
| 日志出现 Core icon collection manifest 提示 | 现有本地核心资源曾出现此提示；记录并区分于插件错误，不要因此把空白页面测试记为通过 |

查看最近日志：

```powershell
Get-Content 'D:\CodeX\kxkms\.local-test\server-error.log' -Tail 80
```

记录问题时注明：操作账号角色、页面地址、复现步骤、预期/实际结果和截图。分享日志前移除密码、密钥及个人信息，不提交 LOCAL-LOGIN.txt。

## 8. 技术人员自动化复测（可选）

脚本会改动测试管理员的秀米绑定信息并创建、清理测试数据，只在可丢弃的本地测试环境运行，不要对正式库执行：

```powershell
Set-Location 'D:\CodeX\kxkms'
& .\.local-test\php\php.exe .\dssast-cms\tests\integration.php .\.local-test\wordpress\wp-load.php
```

自动化通过不替代“添加赛事是否空白”的浏览器验证。详细测试记录见 [TESTING.md](TESTING.md)。旧版 [ADMIN-GUIDE.md](ADMIN-GUIDE.md) 中关于没有统一控制台、没有笔记列表、赛事单页不展示字段的描述已由 0.3.0 更新，当前操作以本文和 README 的版本说明为准。
